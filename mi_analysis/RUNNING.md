# Running this benchmark analysis

This directory contains completed notebooks and their regenerated dependencies. The model is the wd=0.1 benchmark, not historical wd=0.01 SEL-4L. `config/analysis_plan.json` defines the model and analysis scope. MB01 verifies frozen reference artifacts; it does not retrain them. MB12 reports retrospective measurements on an already accessed test split.

Run notebooks from within this repository using Python 3.12 and the packages in `requirements-rerun.txt`. The environment used here is recorded in `config/execution_environment.json`; computation uses CPU with four threads. Select that Python environment as the notebook kernel. Default notebook paths resolve to `mi_analysis/`; `MI_ANALYSIS_DIR` overrides the output folder when explicitly set.

The five full-model checkpoints, context-only checkpoint, reference checkpoints, prepared events and Track A artifacts remain in `model_training_evaluation/`. External model/config paths and SHA-256 values are recorded relative to this repository in `manifests/external_model_inputs.json`. These large inputs are dependencies, not duplicate copies. Frozen reference artifacts and all generated MI outputs are included here.

Execution order: MB01, MB02, MB07R, MB03, MB04, MB05, MB06, MB07, MB08, MB09, MB10, MB11, MB11b, MB11c, MB12, MB13. MB07R verifies instrumentation before the more expensive analyses. MB07 records each completed primary-seed head ablation with a matching input/code hash so interrupted CPU runs can resume; it evaluates batches of 512 rows while keeping the full event population and the same five resampling draws. Use full mode (`MI_RUN_MODE=full`); smoke mode changes scientific sample sizes and is not this run. The staging runner is `scripts/run_mi_notebooks.py` in the repository root. It uses `.mi_analysis_rerun/`, saves completed cells and status, and publishes each notebook to `mi_analysis/` only after successful completion. Initialization/fix scripts refuse to overwrite existing execution results.

`manifests/MB*_completed_dependencies.json` records each notebook's inputs and dependencies at completion. A later notebook may deliberately generate or update shared configuration/results; its newer completion record describes that later state. `manifests/source_change_log.jsonl` and `artifacts/source_versions/` preserve intentional source amendments. Run the provenance audit rather than silently accepting changed input hashes.

Already examined test data cannot provide a fresh blind confirmation. Ordinal/spatial adjacency analyses remain disabled until source-confirmed category semantics are available. These limitations are scientific scope constraints and are not silently replaced by guessed mappings.
